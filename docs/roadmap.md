To extend the findings of this study in future revisions, follow-up experiments are prioritized below by engineering value:

1. **Multi-Trial Warm vs. Cold Latency Distributions:** Execute 5–10 repeated runs of the 64K and 128K coding and retrieval fixtures across both cold-unloaded and warm-cached states to establish median and interquartile range (IQR) bands alongside the baseline point measurements.
2. **Sub-Second VRAM Headroom and Commit Tracing:** Continuously log GPU VRAM, WDDM shared memory, physical RAM, and OS commit charge across full 128K `deep` coding and compaction cycles under active desktop multitasking to tune the `1,536 MiB` VRAM reserve and eliminate transient `0 MiB free VRAM` warnings.
3. **Longitudinal Production Compaction Audits:** Evaluate 10–20 natural production compactions triggered at the `81,920`-token bound to measure post-compaction file re-read rates and long-horizon task retention across multi-hour coding sessions.
4. **Controlled `PLE` Direct NVMe vs. DRAM Micro-Benchmark:** Run an isolated A/B latency comparison between `PLE = direct` NVMe and `PLE = RAM` at 32K and 64K contexts to quantify the exact latency delta of saving 26.8 GiB of host RAM.
5. **Non-Preemptive Priority Queueing for Short Verification Jobs:** Introduce a two-tier priority lane in `OCF V1` so short interactive verification fixes (such as the 7-minute `Job D`) can be scheduled ahead of multi-job background waves (`Job B` and `Job C`) when the single inference slot releases, while cleaning up the legacy `>120m` status text in `ocf-status`.
6. **Direct Cloud-Billed vs. Local Token Telemetry Pairing:** *(Partially addressed in v1.2.0 by list-price counterfactuals:* `docs/full-token-cost-report-2026-11-08.md` applies published per-million rates to the full recorded OpenCode ledger, establishing the local side and a modeled cloud band of **$8.43–$259.48** ($275.13 for the Teams-plus-CTR case). **Still missing:** pairing *billed* cloud orchestrator token receipts (separating cached vs. uncached input and output tokens) with local `OpenCode` token logs across matched repository slices to establish a standardized financial offload ratio; counterfactual list-price arithmetic is not an invoice.)
